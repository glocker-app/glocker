# Architecture

## Overview

Glocker is a Linux distraction blocker written in Go. A root daemon (started by
systemd) enforces blocks through `/etc/hosts`, process killing, sudoers edits and
browser extensions. The same `glocker` binary is the CLI; it talks to the daemon
over a Unix socket. A separate service, glockpeek, is a database-backed dashboard
that the daemon syncs its records to.

## Configuration

The agent config is `/etc/glocker/config.yaml`, copied from `conf/conf.yaml` at
install (root:glocker 0640, `chattr +i`). Blocklists in `/etc/glocker/conf.d/` are
included from `domains.list` via `!include`. The config is nested by feature:

```yaml
user: "yourusername"          # managed account (sudoers, usage monitor, glocker group)
domains:
  enabled: true
  hosts_path: "/etc/hosts"
  kill_on_block: [firefox, chromium]
  blocked_access_command: ""
  unblocking: {reasons: [...], log_file: ..., temp_unblock_time: 30, max_per_day: 0}
  list:
    - {name: "reddit.com"}                       # no windows: always blocked
    - name: "youtube.com"
      unblockable: true
      block_windows: [{start: "09:00", end: "17:00", days: [Mon, Tue, Wed, Thu, Fri]}]
    - !include conf.d/personal-domains.yaml
programs:
  enabled: true
  check_interval_seconds: 5
  list:
    - {name: "steam", allow_windows: [{start: "19:00", end: "22:00", days: [Fri, Sat]}]}
    - {name: "firefox", extendible: true, kill_windows: [{start: "22:00", end: "05:00", days: [...]}]}
content:
  monitoring: {enabled: true, log_file: "/var/log/glocker/reports.log"}
  keywords: {url_keywords: [...], content_keywords: [...], whitelist: [...]}
sudoers: {enabled: true, allowed_sudoers_line: ..., blocked_sudoers_line: ..., allow_windows: [...]}
mindful_uninstall: {enabled: true}
lifecycle: {log_file: ..., reasons: [...]}
violation_tracking: {enabled: true, max_violations: 5, time_window_minutes: 60, command: ...}
usage_monitor: {enabled: true, ...}
heartbeat: {enabled: true, interval_minutes: 30, ...}
sync: {enabled: false, glockpeek_url: ..., token: ..., encrypt: false}
accountability: {enabled: false, buddy_emails: [...], ...}   # acted on by glockpeek
panic: {enabled: true, command: "systemctl suspend", duration: 30}
```

See `conf/conf.yaml.sample` for every field. The loader rejects the old flat
format (`web_tracking`, `forbidden_programs`, `extension_keywords`, top-level
`kill_on_block`, `panic_command`, `tamper_detection`, ...) with a pointer to the
new location (`internal/config/loader.go`).

Time windows are `HH:MM` start/end plus day names; a window whose end is before
its start crosses midnight and belongs to the day it started
(`utils.InAnyWindow`).

## Daemon

`glocker -daemon` refuses to run unless euid is 0. Startup
(`cmd/glocker/main.go`):

1. Load config, log `envcheck` warnings, restore program extensions.
2. Open the IPC socket.
3. Start goroutines:
   - forbidden-programs monitor (if `programs.enabled`)
   - violation reset loop (if `violation_tracking.enabled`)
   - panic monitor (if `panic.enabled`)
   - web server (if `domains.enabled` or `content.monitoring.enabled`)
   - usage monitor (if `usage_monitor.enabled`)
   - syncer (if `sync.enabled`)
4. `InitialEnforcement`, then `EnforcementCheck` every 60s (fixed).

### Enforcement loop (`internal/enforcement`)

`InitialEnforcement` writes `/etc/hosts` and sudoers, records the hosts file's
SHA-256, caches the time-windowed and unblockable domain names, then sets
`cfg.Domains.List = nil` to free the full list.

`EnforcementCheck` rewrites `/etc/hosts` only when:
- the number of temporary unblocks changed,
- a time-windowed domain changed state, or
- the hosts file hash no longer matches (it is rewritten from config).

A rewrite reloads the config from disk to get the full domain list. Sudoers is
rewritten when the allow-window state flips.

### Hosts file

`UpdateHosts` keeps every line above `### GLOCKER START ###` and replaces
everything from the marker down. Below the marker it writes a
`glocker.localhost` alias, then for each domain `127.0.0.1` and `::1` entries
for `domain` and `www.domain`. The file is `chattr -i` before and `chattr +i`
after the write.

### Sudoers

The line tagged `# GLOCKER-MANAGED` in `/etc/sudoers` is swapped between
`allowed_sudoers_line` (inside `allow_windows`) and `blocked_sudoers_line`
(outside them). Edits go to a temp file, are checked with `visudo -c`, then
renamed into place. `glocker -lock` forces the blocked line until the window logic next
switches sudo to allowed.

### Forbidden programs (`monitoring/forbidden.go`)

Every `check_interval_seconds` (default 5), each program is evaluated:
- in a `kill_windows` window: killed
- else if `allow_windows` is set: killed outside them
- else if no windows: always killed
- an active extension (`extendible: true`, `glocker -extend`) keeps it alive

Matching is a case-insensitive substring of the process `comm`; processes
containing glocker/systemd/kernel and PID 1 are skipped. Kill is TERM, then
KILL after 2s. A kill records a violation and appends a `forbidden_program`
entry to the reports log.

Extensions last 1 hour, at most one per program per rolling 24h, persisted in
`/var/lib/glocker/extensions.json` and logged to the unblocks log as
`program:<name>`.

`domains.kill_on_block` uses the same matcher right after `-block` to flush
browser DNS caches; it ignores windows and is not a violation.

### Violations (`monitoring/violations.go`)

Sources: blocked-domain hits on the web server (`web_access`), extension
reports (`content_report`), and program kills (`forbidden_program`). Each is
kept in memory and also appended to `reports.log`. After each one, violations
in the last `time_window_minutes` are counted; at `>= max_violations` the
`command` runs (again on every further violation). The in-memory list is cleared
once a day, in the midnight hour.

`violation_tracking.command`, `domains.blocked_access_command` and
`panic.command` are split on whitespace and executed directly (no shell) as
root.

### Panic mode (`monitoring/panic.go`)

`glocker -panic` sets a deadline `panic.duration` minutes ahead (default 30).
The panic goroutine polls every second and, while the deadline is in the
future, runs `panic.command`, with a 5s grace after each run. Refused if
`panic.enabled` is false.

### Web server (`internal/web`)

HTTP on `127.0.0.1:80` and `[::1]:80`, HTTPS on `:443` of both, with a
self-signed certificate generated in memory. Routes:

- `/` — catch-all. If the Host (or a parent domain) is a currently blocked
  config domain, record the violation, run `blocked_access_command`, and redirect
  to `/blocked?domain=&matched=&url=`. Lookups load the config on first sight of
  a host and cache the result.
- `/blocked` — renders the blocked page (`blocked.go`).
- `/keywords` — JSON: `url_keywords`, `content_keywords` (content + URL
  keywords), `whitelist` (`glockerapp.com` prepended).
- `/keywords-stream` — SSE with the same payload.
- `/report` — POST from the extensions; ignored for loopback/`*.localhost`/
  `glockerapp.com`; otherwise recorded and appended to `reports.log`.

## CLI and IPC

The binary is installed `0755`, not setuid. The socket
`/var/glocker/glocker.sock` is root:glocker `0660` in a `0750` directory, and
install adds `user` to the `glocker` group, so the managed user can run most
commands without sudo. `uninstall` and `resync` additionally require the peer's
real uid to be 0 (checked with `SO_PEERCRED`).

Protocol: one line `action[:payload]` per connection, then the daemon closes.
Actions (`ipc/server.go`):

| Action | Payload | Effect |
|---|---|---|
| `ping` | | replies `pong` (used by glockdoc) |
| `status` | | runtime status, ends with `END` |
| `info` | | config summary, ends with `END` |
| `unblock` | `domains:reason` | temporary unblock |
| `block` | `domains` | add domains, then kill `kill_on_block` |
| `block-app` | `programs` | add programs (no windows), kill now |
| `extend` | `program:reason` | one-hour extension |
| `add-keyword` | `keywords` | add to URL and content keywords |
| `lock` | | force sudoers to the blocked line |
| `panic` | | start panic mode |
| `resync` | `[since_ms]` | re-push records to glockpeek |
| `uninstall` | `reason[:note]` | restore system, reply `COMPLETED`, exit |

Other replies are a single `OK: ...` or `ERROR: ...` line.

`block`, `block-app` and `add-keyword` are in-memory only; nothing writes the
config file, so they last until the daemon restarts.

Unblock rules: the reason must be in `domains.unblocking.reasons` (if set); a
domain in the config must be `unblockable: true`; an already-active unblock is
skipped; `max_per_day` (0 = unlimited) is counted from the unblocks log.
Duration is `temp_unblock_time` minutes (default 30).

Other flags handled by the client without the socket: `-install`, `-init`,
`-check`, `-connect`, `-version`.

## Install and uninstall

`glocker -install` (root): validate config, stop a running daemon, copy config
and `conf.d/`, install `glocker`/`glocklock`/`glockpeek`/`glockdoc`, make the
binary and config immutable, add the user to `glocker`, schedule glockdoc (systemd
timer, else cron), install browser policies and the GNOME extension, install and
start `glocker.service` and `glockpeek.service`, log an install event.

`glocker -uninstall <reason>` (root): validate the reason against
`lifecycle.reasons`, run the mindful gate if enabled, then send `uninstall` to
the daemon, which logs the event, restores `/etc/hosts` and sudoers, removes
browser policies, config, socket and service, and exits. The glockdoc watchdog
is left in place unless `-purge` is given, so it records the downtime.

### Mindful uninstall (`internal/mindful`)

A typing challenge: characters of a random sentence are revealed on a fixed
beat and must be typed as they appear; falling behind, a typo, or losing focus
restarts with a new sentence. If the lifecycle log has an uninstall within
`recency_hours` (default 24), the target grows to `recent_lines` sentences
(default 3). If the gate can't run (no tty), the uninstall is refused.

## Browser extensions

Both are force-installed by browser policy:

- Firefox (`extensions/firefox`, MV2): the signed xpi goes to
  `/usr/local/share/glocker/glocker.xpi`; install merges an `ExtensionSettings`
  entry and `DisablePrivateBrowsing` into `/etc/firefox/policies/policies.json`,
  recording prior values so uninstall can restore them.
- Chrome family (`extensions/chrome`, MV3): install writes `glocker.json` into
  the managed-policy dirs of Chrome, Chromium, Brave and Edge. It force-installs
  from `https://glockerapp.com/chrome/update.xml` and disables incognito, guest
  mode, secure DNS and Brave Tor. URL blocking uses `declarativeNetRequest`
  redirect rules.

Both fetch `/keywords`, follow `/keywords-stream`, redirect matches to
`http://127.0.0.1/blocked`, and POST `/report` with trigger
`url-keyword:<kw>` or `content-keyword:<kw>`. URL keywords must start a word;
content keywords match on word boundaries. Whitelisted domains are skipped.

## glockpeek and sync

glockpeek (`cmd/glockpeek`) is a separate service with its own config
(`/etc/glocker/glockpeek.yaml`). It stores records via GORM (sqlite or
postgres, `internal/store`), serves the dashboard and JSON API
(`internal/stats`), accepts records on `/api/ingest`, and sends account and
accountability email via Mailgun. The agent sends no email.

The agent's syncer (`internal/syncer`) reads the local logs (violations,
unblocks, lifecycle, usage, heartbeat), does a backfill at startup, then
incremental pushes every `sync.interval_seconds` (default 300) to
`sync.glockpeek_url` (default `http://127.0.0.1:4317`). Ingest is idempotent.
It also uploads a summary of the config (no full domain lists) to `/api/config`
when it changes. With `sync.encrypt: true` sensitive fields are encrypted
client-side with the key installed by `glocker -connect` (default
`/etc/glocker/e2e.key`); `encrypt` must be set explicitly when sync is enabled.
Local logging and enforcement do not depend on glockpeek being reachable.

## Runtime paths

| Path | Contents |
|---|---|
| `/usr/local/bin/glocker` | binary, 0755, immutable |
| `/etc/glocker/config.yaml`, `/etc/glocker/conf.d/` | config, immutable |
| `/var/glocker/glocker.sock` | IPC socket |
| `/var/log/glocker/reports.log` | violations (web access, keywords, program kills) |

| `/var/log/glocker/heartbeat.jsonl` | glockdoc liveness samples |

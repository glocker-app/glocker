A distraction blocker for Linux

glocker blocks distracting websites, on-page content, and applications on a schedule you set. You own the machine, so it can’t lock you out for good — instead it makes switching it off slow and deliberate.

How it works

Websites

Sites and whole blocklists you name are routed nowhere, through /etc/hosts.

On-page content

A Firefox extension scans page text for keywords you set — catching what a domain block can’t, like a search result or a feed.

Applications

Named programs are closed the moment they launch during a blocked window.

Violation limit

Too many attempts to reach blocked content within a set window and the screen is locked, via glocklock.

Blocking on Linux is hard

The problem is root: on your own machine you have it, and root can undo anything. Editing /etc/hosts, stopping the service, killing the daemon, uninstalling it — all of it needs root. glocker’s answer is to withdraw your sudo during the hours you set, so in those windows there’s no root to undo it with.

Outside those hours, or as real root, it stays deliberate: /etc/hosts and glocker’s own binary are made immutable (chattr +i) and restored every cycle, so a quick edit won’t stick.

Uninstalling

Uninstalling is deliberately slow. glocker -uninstall asks for a stated reason, then starts a metronome-paced typing challenge: you retype a passage one keystroke per beat, and any mistake starts it over. Only once it’s finished does glocker drop the immutable flags, restore /etc/hosts and the sudoers rules, and remove the service.

glockdoc, a small watchdog, survives the uninstall — so even a completed teardown is recorded rather than silent.

Room for real work

Blocking isn’t the whole point — you still need the machine. Every exit is possible, and written to the log:

Timed unblock
Open a specific domain for a set length of time, with a reason.
An app for an hour
Grant a sometimes-needed app one hour of runtime a day.
Accountability
Slips and unblocks can email someone you chose.

glockpeek is the dashboard. It reads the records back — what was blocked, what you unblocked, and how your time was spent. Run it locally, where the data stays on your machine, or use the hosted one.

Why I made it

I built glocker for my own use, because nothing else fit my setup, and I’ve been running it for over a year.

The programs

glocker isn’t one binary but a few small programs, each doing one job and keeping an eye on the others.

glocker
The daemon; applies the blocking and records every event locally.
glockpeek
The dashboard; reads the records back, locally or hosted.
glockdoc
The watchdog; checks the daemon is alive and survives an uninstall.
glocklock
The screen locker; behind the violation lock and the uninstall gate.
Firefox extension
Scans page content for your keywords and reports matches.

Getting it

Everything’s on GitHub. Copy the sample config, edit it to taste, then one command builds glocker, pulls the blocklists from curated sources, and installs the lot.

# clone, configure, and go
$ git clone github.com/nibrahim/glocker
$ cp conf/conf.yaml.sample conf/conf.yaml
$ $EDITOR conf/conf.yaml
$ make full-install

Rather not run a server? A hosted option is coming: install just the agent and let the dashboard and accountability email live on glockerapp.com for a small subscription. See the setup guide.
